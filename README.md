## 💡 2. 9주차 추가 및 개선 기능
사용자의 폼 입력 오류를 줄이고 제출 경험을 개선하기 위해 아래 기능을 적용했습니다.

### ① 폼 구성 및 조건부 입력 (UI 개선)
- **추가 입력 사항:** `textarea`를 활용하여 10자 이상의 구체적 식단 요청사항을 받도록 설계했습니다. 도움말(help-text)을 덧붙여 명확한 입력을 유도했습니다.
- **알레르기 조건부 렌더링:** '알레르기가 있습니다' 체크박스를 선택(`change` 이벤트)했을 때만 상세 입력 인풋창의 `display`가 나타나고 `disabled`가 해제되도록 제어했습니다.

### ② 실시간 입력 검증 및 피드백 (Validation)
- **글자 수 조건:** 요청사항 란에 `input` 이벤트를 걸어 실시간으로 `0/100` 형태의 글자 수를 세어 화면에 출력합니다.
- **시각적 오류 해제:** 10자 미만일 경우 붉은색 테두리와 ❌ 경고 문구를 띄우며, 10자를 넘기는 순간 즉시 초록색 테두리와 ✅ 성공 문구로 바뀌어 사용자가 안심할 수 있게 구현했습니다.

### ③ 제출 상태 처리 및 중복 방지 (form `submit`)
- 일반 버튼 클릭이 아닌 `<form>`의 `submit` 이벤트로 전체 검증 및 동작을 묶었습니다.
- 제출 조건을 하나라도 어기면 `preventDefault()` 후 누락된 폼으로 `.focus()` 시킵니다.
- **제출 중/중복 방지:** 모든 조건 통과 시 제출 버튼을 비활성화(`disabled = true`)하고 "⏳ 데이터 검증 및 서버 전송 중..." 문구를 띄워 중복 제출(다중 클릭)을 방지합니다.

## 🔄 3. 오류 실패 처리 및 확인(테스트) 순서

### 테스트 순서 시나리오
1. **조건부 토글 테스트:** '알레르기 여부'를 체크/해제하며 텍스트 칸이 숨겨지거나 나타나는지 확인합니다.
2. **빈 값 / 오류 수정 테스트:** 요청사항을 9자 이하로 적었을 때 붉은 경고가 뜨고 10자 이상 적었을 때 해제되는 것을 확인합니다.
3. **제출 차단 테스트:** 필수 항목이 비어있을 때 하단에 오류 문구가 나타나며 제출이 막히는지 점검합니다.
4. **실패 복구 테스트 (실패 시뮬레이션):** 
   - `script.js` 내에 이름에 **'오류'**라는 단어가 들어가면 `setTimeout` 통신 후 실패하도록 강제 예외 처리를 두었습니다.
   - 이름 입력 칸에 `오류테스트`라고 적은 뒤 제출해 봅니다. 버튼이 1.5초간 비활성화된 후 제출에 실패하며, **입력했던 내용들이 그대로 보존된 채 버튼만 원상 복구**되는 것을 확인합니다.
5. **초기화 확인:** 다시 시작 버튼을 눌렀을 때 입력값뿐만 아니라 에러 문구, 글자 수 카운터, 알레르기 체크 상태까지 모두 깔끔하게 초기화되는지 확인합니다.
