## 💡 2. 10주차 구현 기능: 내비게이션 UI와 정보 탐색

### ① 서비스 메뉴 구성 및 현재 위치 표시 (`aria-current`)
- **메뉴 구성:** `<nav>`와 `<ul>·<li>` 구조로 **서비스 소개(`#about`)**, **추천 식단(`#tabs`)**, **무료 체험 신청(`#contact`)** 3가지 메뉴를 연결했습니다.
- **현재 위치 동기화:** 메뉴 클릭, 화면 스크롤(`scroll`), 새로고침(`DOMContentLoaded`), 브라우저 뒤로 가기(`hashchange`) 시 실제 화면 위치와 일치하는 메뉴에 `aria-current="page"`를 적용하고 흰색 배경으로 하이라이트합니다.

### ② 신청 내역 목록 필터 및 결과 안내 (`aria-pressed`)
- **필터 기준:** 완료 화면(Step 3)의 신청 내역을 건강 목표 기준(**전체**, **다이어트**, **벌크업**, **건강 유지**) 4가지 버튼으로 필터링합니다.
- **상태 및 빈 결과 구분 안내:** 선택된 필터 버튼은 `aria-pressed="true"`로 표시되며, 상단에 `표시된 신청 내역: N건`을 실시간으로 안내합니다. 또한 **전체 내역이 0건인 경우**와 **특정 필터 조건의 결과만 0건인 경우**의 안내 문구를 구분하여 표시합니다.

### ③ 모바일 메뉴 구현 (`aria-expanded`)
- 화면 폭 768px 이하에서 `메뉴 열기 ☰` 버튼이 나타나며, 클릭 시 `aria-expanded` 값(`false` ↔ `true`)과 버튼 문구(`메뉴 닫기 ✕`)가 함께 전환됩니다.
- 메뉴에서 목적지를 선택하면 해당 섹션으로 이동한 뒤 펼쳐진 메뉴가 자동으로 닫힙니다.

## 💡 3. 9주차 구현 기능: 폼 UI와 입력 경험 설계
- **조건부 입력:** '알레르기가 있습니다' 체크 시 상세 입력창이 표시되고 `disabled`가 해제됩니다.
- **실시간 검증 및 피드백:** 추가 요청사항 입력 시 `0/100` 글자 수와 함께 10자 미만 오류(붉은색) 및 충족 완료(초록색) 상태를 실시간으로 표시합니다.
- **제출 상태 처리:** `form`의 `submit` 이벤트로 검증 후 제출 중 버튼을 비활성화하여 중복 제출을 방지하며, 이름에 `'오류'` 입력 시 입력 내용을 유지한 채 재시도할 수 있는 실패 처리를 확인할 수 있습니다.

## 🔄 4. 기능 확인 조작 순서 (테스트 시나리오)
1. **내비게이션 및 뒤로 가기 확인:** 상단 메뉴 클릭으로 이동 → 브라우저 **뒤로 가기** 클릭 → **새로고침** 후에도 상단 메뉴 하이라이트(`aria-current`)가 현재 화면 섹션과 일치하는지 확인합니다.
2. **모바일 메뉴 확인:** 개발자 도구(F12)에서 화면 폭을 390px로 줄인 뒤 `메뉴 열기 ☰` 클릭 → 메뉴가 펼쳐지고 `aria-expanded="true"`로 바뀌는지 확인 → 목적지 메뉴 클릭 시 이동 후 메뉴가 자동으로 닫히는지 확인합니다.
3. **폼 입력 및 제출 흐름:** `무료 체험 신청`에서 알레르기 체크 후 상세 내용을 적고, 요청사항을 10자 이상 입력하여 `최종 신청 확정하기`까지 진행합니다. (다이어트 1건, 벌크업 1건 추가 신청)
4. **목록 필터 및 빈 결과 확인:** `나의 신청 내역 탐색`에서 **전체(2건)** → **다이어트(1건)** → **건강 유지(0건 - 조건 불일치 안내)** 순으로 필터를 눌러 개수와 안내 문구 변화를 확인하고, 모두 취소 시 **전체 내역 없음 안내**가 출력되는지 확인합니다.
